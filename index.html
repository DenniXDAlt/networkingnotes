Scenario 1

Sales Tablet → Router 1 → Router 2 → DB Server

Your original scenario

A salesperson keys in sales data on a tablet. The data must reach the DB Server on a remote network.

Device Table

DeviceRoleIPv4 AddressMAC
Sales-TabletSource Host192.168.1.10/24AA-AA
R1 G0/0LAN Interface (Default GW)192.168.1.1/24BB-BB
R1 S0/0WAN Interface10.0.0.1/30CC-CC
R2 S0/0WAN Interface10.0.0.2/30DD-DD
R2 G0/0LAN Interface172.16.1.1/24EE-EE
DB-ServerDestination172.16.1.50/24FF-FF

Network Diagram

Phase Summary

Phase 1 — Source Packaging

Sales app data encapsulated down the stack. App data → Segment (+ port) → Packet (Src IP: 192.168.1.10, Dst IP: 172.16.1.50) → Frame (Src MAC: AA-AA, Dst MAC: BB-BB) → bits via radio waves (Wi-Fi).

Phase 2 — Local Discovery

Tablet checks: 172.16.1.50 is NOT on 192.168.1.0/24 → use default gateway R1 (192.168.1.1). ARP broadcast (FF-FF-FF-FF-FF-FF) for R1's MAC. R1 replies unicast: BB-BB. ARP cached.

Phase 3 — Gateway Transition

R1 accepts (Dst MAC = BB-BB), de-encapsulates, reads Dst IP 172.16.1.50, routing table → via R2 (10.0.0.2). Re-encapsulates: Src CC-CC, Dst DD-DD. R2 repeats: finds 172.16.1.50 on G0/0, ARPs for FF-FF, re-encapsulates: Src EE-EE, Dst FF-FF.

Phase 4 — Arrival & De-encap

DB Server NIC: Dst MAC FF-FF ✓, FCS valid → strips L2. IP: Dst 172.16.1.50 ✓ → strips L3. Transport: hands data to DB application via port. Sales data successfully written to DB.

Full presentation script (all 4 phases)
🎤 Script — Scenario 1: Tablet → DB Server
Phase 1:
[Point to the Tablet] "So the scenario is a salesperson keying in sales data on a tablet, and that data needs to reach the DB Server on a different network.

The data gets encapsulated — basically, it adds things layer by layer going down the OSI stack. The sales app is at Layer 7. Then Layer 4 adds the port number, turning the data into a segment. Layer 3 adds the source IP 192.168.1.10 and destination IP 172.16.1.50 — turning it into a packet. Layer 2 adds the MAC addresses — source MAC AA-AA, destination MAC BB-BB, which is the router — turning it into a frame. Layer 1 then converts the frame into bits, which in this case are transmitted as radio waves since it's Wi-Fi."

Phase 2:
[Point to the tablet and R1] "Before the tablet can send anything, it needs to figure out where to send it. It checks if the destination 172.16.1.50 is on the same network. It's not — so it has to send through the default gateway, R1 at 192.168.1.1.

To find R1's MAC, the tablet sends an ARP Request — a broadcast to FF-FF-FF-FF-FF-FF, asking who has 192.168.1.1. R1 hears it and sends a unicast ARP Reply back with its MAC BB-BB. The tablet saves this in its ARP cache."

Phase 3:
[Point to R1 then R2] "The frame arrives at R1. R1 checks the destination MAC — it's BB-BB, matches its own interface, so it accepts. R1 de-encapsulates the Ethernet header and reads the destination IP: 172.16.1.50. It checks its routing table — basically an internal map of the network — and finds the route goes through R2. It re-encapsulates the packet with new MACs: source CC-CC, destination DD-DD, and forwards it to R2.

R2 does the same thing — de-encapsulates, reads the IP, finds 172.16.1.50 is directly connected on its G0/0 interface, ARPs for the DB server's MAC FF-FF, re-encapsulates with source EE-EE, destination FF-FF, and sends it out."

Phase 4:
[Point to DB Server] "The frame arrives at the DB Server. The NIC checks the destination MAC — FF-FF, matches — so it accepts the frame. It checks the FCS trailer for errors, strips the Ethernet header, and passes the packet up. Layer 3 checks the destination IP — 172.16.1.50 — matches. Strips the IP header, passes the segment up. Layer 4 reads the port and pushes the data to the database application. The sales data is now successfully received and can be written to the database."

🎤 Script — Scenario 3: PC → R1 → R2 → R3 → Web Server
Phase 1:
[Point to PC-Work] "The workstation is sending an HTTP request to a web server three hops away. The data gets encapsulated layer by layer — application data becomes a segment at Layer 4, then a packet at Layer 3 with source IP 192.168.10.5 and destination IP 172.20.1.10, and a TTL value of 128. Layer 2 wraps it into a frame with source MAC AA-AA and destination MAC BB-BB — which is R1 — and Layer 1 sends it as bits."

Phase 2:
[Point to the PC's subnet] "The PC checks: is 172.20.1.10 on the same network as me, 192.168.10.0/24? No. So it goes through the default gateway R1. The PC broadcasts an ARP Request, R1 replies with MAC BB-BB, and the frame is built."

Phase 3:
[Trace finger across R1 → R2 → R3] "This scenario has three router hops, and this is the important thing — at every single hop, the MAC addresses change, but the IP addresses stay the same.

R1 accepts the frame, de-encapsulates, reads destination IP 172.20.1.10, decrements TTL from 128 to 127, looks up routing table — next hop is R2 — re-encapsulates: source CC-CC, destination DD-DD.

R2 does the same. De-encapsulates, TTL drops from 127 to 126, re-encapsulates: source EE-EE, destination FF-FF.

R3 does the same. TTL drops from 126 to 125. R3 finds 172.20.1.10 directly connected, ARPs for the web server MAC 22-22, re-encapsulates: source 11-11, destination 22-22."

📖 Key Concept Notes — Default Gateway, ARP, MAC, Routing & More
Default Gateway
The default gateway is the router interface on the same subnet as the host. When a host wants to send data to any IP address outside its own subnet, it sends the frame to the default gateway's MAC address instead.

How the host decides: It performs a bitwise AND between the destination IP and its subnet mask. If the result equals the host's own network address → local. If different → remote, use the default gateway.
Host IP: 192.168.1.10 /24
Destination: 172.16.1.50
Network match? NO → remote → send to default gateway

Destination: 192.168.1.50
Network match? YES → local → ARP for destination directly
ARP — Address Resolution Protocol
ARP resolves an IP address to a MAC address. Before a host can send a frame, it needs to know the MAC of the next hop (either the destination on the same LAN, or the default gateway on a remote LAN).
ARP Request (broadcast):
Dst MAC: FF-FF-FF-FF-FF-FF ← sent to everyone on LAN
Src MAC: AA-AA Src IP: 192.168.1.10
Target IP: 192.168.1.1 ← who has this IP?

ARP Reply (unicast):
Dst MAC: AA-AA Src MAC: BB-BB
"192.168.1.1 is at BB-BB" ← stored in ARP cache
Important: ARP broadcasts are never forwarded by routers — they stay within the local subnet. The ARP cache stores recent mappings to avoid repeated broadcasts (expires after ~2–20 min).
MAC Addresses — Hop-to-Hop vs IP Addresses — End-to-End
This is the most important concept in Phase 3. Understand why they behave differently:
IP Addresses: NEVER change end-to-end
Src IP = original sender all the way to destination
Dst IP = final destination all the way from source

MAC Addresses: change at EVERY router hop
Only meaningful on the current local link segment
Router strips old MAC, adds new MACs for next segment
Think of it like a parcel delivery: the address label (IP) always says "from Alice to Bob". But the delivery truck (frame/MAC) changes at every distribution centre (router) depending on which local route is used next.
Encapsulation & PDU Names
Layer 7 (Application): Data / Message
Layer 4 (Transport): Segment (+ source/destination port)
Layer 3 (Network): Packet (+ source/destination IP, TTL, Protocol)
Layer 2 (Data Link): Frame (+ source/destination MAC, EtherType, FCS)
Layer 1 (Physical): Bits (electrical / light / radio signals)
De-encapsulation is the reverse — each layer strips its own header as the data travels UP the stack at the receiver.
TTL — Time To Live
TTL is a field in the IPv4 header. It starts at a value set by the source OS (commonly 128 for Windows, 64 for Linux/Mac) and is decremented by 1 at every router. If TTL reaches 0, the router discards the packet and sends an ICMP Time Exceeded message back to the source. This prevents packets from looping forever.
PC sends: TTL = 128
→ R1 receives: TTL 128 → 127, forwards
→ R2 receives: TTL 127 → 126, forwards
→ R3 receives: TTL 126 → 125, forwards
→ Destination receives packet with TTL = 125
What a Router Does at Each Hop (Phase 3 Detail)
Four clear steps at each router:
1. Accept — NIC checks incoming Dst MAC matches its own interface MAC
2. De-encap — Strip Ethernet header + FCS trailer, expose IPv4 packet
3. Route — Read Dst IP, look up routing table, find next hop, decrement TTL
4. Re-encap — Build new Ethernet frame with new Src/Dst MACs for next link
The routing table is the "internal map" — it stores network prefixes and which interface/next-hop to use for each one. If no match is found, the router uses a default route (0.0.0.0/0) if one is configured, or drops the packet.
Layer 2 Devices: Switch vs Wi-Fi AP
Switch:
Operates at Layer 2 only
Maintains a MAC address table (learns which port = which MAC)
Forwards frames to the correct port based on Dst MAC
Floods unknown Dst MACs and broadcasts to all ports
Does NOT modify IP, MAC, or TTL — purely passes the frame

Wi-Fi Access Point (AP):
Also Layer 2 — acts as a wireless bridge
Converts 802.11 wireless frames ↔ Ethernet wired frames
Does NOT route — no IP changes, no TTL changes
ARP broadcasts pass through the AP to the wired network
Key: Neither a switch nor an AP is involved in Phase 3 routing — they are transparent Layer 2 forwarders. Only routers perform de-encapsulation and re-encapsulation at Layer 3.
FCS / CRC — Frame Check Sequence
The FCS (Frame Check Sequence) is a 4-byte CRC value appended as an Ethernet trailer. The sender calculates it from the frame contents. The receiver recalculates it on arrival — if the values don't match, the frame was corrupted in transit and is silently discarded at Layer 2. This is error detection only, not error correction — the upper layers (TCP) handle retransmission.
EtherType & Protocol Fields
Ethernet EtherType field (Layer 2 header):
0x0800 = IPv4 payload
0x86DD = IPv6 payload
0x0806 = ARP payload

IPv4 Protocol field (Layer 3 header):
0x06 (6) = TCP segment inside
0x11 (17) = UDP segment inside
0x01 (1) = ICMP message inside
These fields tell each layer's protocol handler what type of data is inside — so the right handler processes it during de-encapsulation.
Common Port Numbers (Layer 4)
You don't need TCP/UDP internals, but know these ports:
Port 80 = HTTP (web browsing)
Port 443 = HTTPS (secure web)
Port 25 = SMTP (sending email)
Port 21 = FTP (file transfer)
Port 22 = SSH (secure remote access)
Port 53 = DNS (domain name resolution)
At Phase 4, the Transport layer reads the destination port to know which application to hand the data to.
